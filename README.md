# 记文法加密系统

把中文（经拼音）或纯拼音，按自定的「记文法」码表替换成 4 位数字串的替音工具。

> **先读这一段**：记文法是**公开码表的替音编码，不是加密**。任何拿到码表的人都能
> 直接解密，也没有密钥概念。它适合「随手记录、防止被一眼看懂的社交/笔记场景」。
> 真正需要保密的内容，请用 AES 等成熟方案。详见 [安全边界](#安全边界)。

## 快速开始

```bash
pip install pypinyin        # 只有「中文加密」需要，纯拼音功能可不装
python jiwenfa.py           # 运行交互式菜单
python build.py             # 打包成单文件 dist\记文法加密器.exe（约 15 秒）
```

打包产物 `build/`、`dist/` 已在 `.gitignore` 中排除，不进版本库。

### 例子

```
中文加密:  你好，世界。
   拼音    nihao，shijie。
   密文    0092 0044 0036 0001 0119，0182 0033 0038 0053 0045 0013。

拼音加密:  ni hao
   密文    0103 0042 0661 0033 0001 0112

   密文    0001,0002          标点与码之间不留空格

解密:      0001,0002  ->  a,b
```

## 码表设计

### 1. 递进映射

第 n 个字母占用 n 个连续码，位置越靠后选择越多：

| 字母 | 码值 | 种数 | | 字母 | 码值 | 种数 |
|---|---|---|---|---|---|---|
| a | 0001 | 1 | | n | 0092~0105 | 14 |
| b | 0002~0003 | 2 | | o | 0106~0120 | 15 |
| c | 0004~0006 | 3 | | p | 0121~0136 | 16 |
| d | 0007~0010 | 4 | | q | 0137~0153 | 17 |
| e | 0011~0015 | 5 | | r | 0154~0171 | 18 |
| f | 0016~0021 | 6 | | s | 0172~0190 | 19 |
| g | 0022~0028 | 7 | | t | 0191~0210 | 20 |
| h | 0029~0036 | 8 | | u | 0211~0231 | 21 |
| i | 0037~0045 | 9 | | v | 0232~0253 | 22 |
| j | 0046~0055 | 10 | | w | 0254~0276 | 23 |
| k | 0056~0066 | 11 | | x | 0277~0300 | 24 |
| l | 0067~0078 | 12 | | y | 0301~0325 | 25 |
| m | 0079~0091 | 13 | | **z** | **0000** | 1 |

`z` 特殊：独占 `0000`，因为它排在最后又只需要 1 个码，用 0000 让密文更好读。

小写占满 `0000~0325`。大写 `A~Y` 用**完全相同的递进规则整体顺延 325**，
即 `A` 与 `a` 形态一致（1 个码）、`Y` 与 `y` 一致（25 个码）：

| 大写 | A | B | … | Y | Z |
|---|---|---|---|---|---|
| 码值 | 0326 | 0327~0328 | … | 0626~0650 | 0651 |

### 2. 保留码

排在字母之后，全部码值共 691 个，最大 `0690`，4 位数字足够容纳。

| 用途 | 码值 | 说明 |
|---|---|---|
| 空白字符（29 种） | 0652~0680 | 含空格 `0661`、制表符、换行、全角空格 U+3000、不换行空格等 |
| 字面数字 0-9 | 0681~0690 | 明文里的数字不再被误判成码 |

这两个块各自解决一个曾经真实存在的缺陷：

- **空白码**——解决两件事。其一，密文里空格既是分隔符又可能来自原文，`nihao` 和
  `ni hao` 会解成一样；用保留码承载原文里的空白（普通空格是 `0661`）后，解密就能
  放心丢弃分隔空格。其二，所有空白都编码后密文里不再出现裸空白，解密时才能无脑跳过
  所有空白，而不会漏掉换行/制表符/全角空格。
- **数字码**——明文里的 `1234` 原本会原样穿过加密器，解密时被当成码表索引而变成 `?`。
  现在 ASCII 数字一律编码。

### 3. 兼容旧密文

`0000~0325` 这个区间**一个字都没有改**。旧版本产生的密文可以继续用新版解密，
只是遇到新版才有的保留码（0652 及以后）时，旧版会显示 `?`。
新增的大写、空白、数字码全部排在 0326 之后，不会挤占历史区间。

## 密文格式

- 每个码写满 4 位，前导 0 补齐
- **只有「码 + 码」相邻时才插一个空格分隔**；标点等原样字符与码之间一律紧贴
- 标点、符号原样保留

这条规则同时覆盖中英文标点，不会出现「逗号前有空格后没有」这类不一致：

```
a,b    ->  0001,0002
a，b   ->  0001，0002
a . b  ->  0001 0661.0661 0002
```

同一字母落在区间内哪个码是随机的，所以 `b` 每次可能是 `0002` 或 `0003`，
上面只是其中一种可能结果。

解密时空白一律丢弃，所以手工换行、手抖多打的空格都不影响结果；
无法识别的码降级成 `?`，方便一眼看出密文有错字。

## 安全边界

请务必理解下面几点，再决定用它做什么：

1. **没有密钥**。码表写死在源码里，公开的。拿到码表 = 拥有解密能力。
2. **不是加密算法**。没有密钥派生、没有认证、没有抗频率分析设计，
   它是一套编码规则，不是密码学。
3. **同字母多码只提供很弱的掩盖**。每个字母随机取区间内的一个码，
   能让「相同字母出现相同码」这个特征被打散，但样本一多统计规律仍会显现。
4. **标点与原样字符不加密**，明文里出现的逗号、括号等会原样出现在密文里。
   顺带一提：**全角数字（如 １２３４）也不加密**，因为码表只收录 ASCII 字符，
   非 ASCII 字符一律原样保留。这是设计取舍，不是 bug。
5. **适合**：个人备忘、给朋友看的趣味暗号、避免被随手扫一眼看懂。
   **不适合**：任何真正需要保密的内容。

## 编码与平台

- 界面符号全部使用 GBK 可编码字符（`● √ × ※ →`）。
  **不要往源码里加 emoji**——Windows 中文控制台默认代码页 936 编不出 emoji，
  一句 `print` 就会抛 `UnicodeEncodeError` 让程序直接崩溃（这个坑踩过一次，
  打包后的 exe 启动即崩）。自检里的「源码 GBK 扫描」就是防这个的。
- `out()` 会在编码失败时按 replace 策略降级，保证程序不会因字符编码退出。
- 读写标准流时统一 `errors='replace'`，控制台、管道、文件三种来源都不会崩。

## 常见问题

**Q: 为什么 `--icon=NONE` 被去掉了？**
A: PyInstaller 没有「无图标」这个参数值，`--icon=NONE` 会被当成去找一个叫 NONE 的
图标文件。默认不传 `--icon` 就是无图标。

**Q: 中文加密报「缺少 pypinyin 库」？**
A: `pip install pypinyin`。这个依赖只影响「中文加密」，拼音加密和解密不需要它。
打包时 build.py 已用 `--collect-data=pypinyin` 带上它的词典数据。

**Q: 能自定义码表吗？**
A: 可以，改 `JiWenFa._build_mapping()`。但要注意保留码别和小写字母的
`0000~0325` 撞号，否则旧密文会解错。
